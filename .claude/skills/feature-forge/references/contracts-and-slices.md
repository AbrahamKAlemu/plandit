# Contracts and slices

Each contract gives outcome, authoritative headings, owned files, authority and
review owner, constraints, dependencies, uncertainty rule, quality checks and
completion evidence. Relevant source selection never forbids necessary code
investigation; raise missing decisions.

Start with a useful end-to-end path. Split at stable interfaces or independent
rollout/rollback boundaries, keeping coupled behavior together. Compatible
prerequisites may land separately with identified consumers and proof. Each
landing keeps the app working. State flags and temporary-path cleanup if needed.

One feature uses one docs pipeline. Agents, workstreams, slices and PRs are
different decisions. Sequence dependencies and assign shared interfaces and
integration explicitly. Test seams on integrated code after merges.

Each slice references the Plan table. PR readiness requires completed behavior
or prerequisite, passing relevant proof, independent review and safe landing.
Make dependent PR order explicit. Reuse evidence only when code and relevant
conditions still match; external/time dependent behavior needs fresh verification.
